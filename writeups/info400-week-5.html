Exercise 14: Defining Two or More Polygons

Overview

Exercise 14 involves using Shapely to define multiple polygons representing adjacent urban areas. The goal is to identify which polygon contains a pick-up location and find the closest cab within that polygon.

Key Concepts

  • Spatial data analysis using Shapely.
  • Defining polygons from coordinate lists.
  • Determining spatial relationships with .within() method.
  • Calculating geographic distances using geopy.

Analysis of Results

The script identifies which polygon contains the pick-up location and determines distances from available cabs within that polygon. It correctly calculates distances and identifies the closest cab based on geographic coordinates.

Critique of AI

Prompt used " Implement spatial grouping of cabs using multiple urban zones and calculate closest distance.”

The result provided correctly structured polygons but misapplied coordinate ordering (longitude vs. latitude). After refinement, the solution properly used Shapely’s .within() for spatial containment checks and geopy’s geodesic distance calculations. The AI’s strength lay in structuring zone-based logic, but manual corrections were required to ensure accurate geographic calculations.

Exercise 15: Further Improving the Pick-Up Algorithm

Overview

Exercise 15 improves upon the previous algorithm by calculating distances for multiple cabs, considering whether they are inside or outside the polygon, and factoring an entry point (like a bridge) into the calculation.

Key Concepts

  • Enhanced spatial decision-making.
  • Conditional logic to differentiate cab positions.
  • Geospatial computations using geopy.distance.

Analysis of Results

The updated algorithm accurately considers both direct and indirect (via entry point) distances. It identifies the closest cab among those provided and clearly outputs the distances calculated.

Critique of AI

Prompt used “Calculate cab distances with entry point routing for geographic barriers."

The generated code proposed straight-line distance comparisons, ignoring real-world routing constraints. The revised solution incorporated conditional pathfinding through a bridge entry point.

Exercise 16: Filtering Data with a List Comprehension

Overview

Exercise 16 demonstrates creating a concise list comprehension to filter data without using pandas. The goal is to identify cabs currently unavailable based on their status.

Key Concepts

  • Python list comprehension for efficient data filtering.
  • Avoiding external dependencies like pandas.

Analysis of Results

The resulting list accurately identified cabs with "open" status, effectively filtering the unavailable cabs from the given dataset.

Critique of AI

Prompt used “Filter orders to unavailable cabs using Pythonic syntax."

The generated list comprehension ([x[2] for x in orders if x[1] == 'open']) was functionally correct but initially used ambiguous tuple indices (x[2]). The refined solution added explicit tuple unpacking for readability

Exercise 17: Adding More Metrics to Analyze Dependencies

Overview

Exercise 17 analyzes stock data to explore relationships between price changes, volume changes, and other calculated metrics. It introduces additional columns for deeper analytical insights, such as rolling sums and price trends.

Key Concepts

  • Time series analysis using pandas.
  • Calculating percentage changes and rolling sums.
  • Assessing correlation between multiple financial metrics.
  • Data-driven financial forecasting insights.

Analysis of Results

The metrics provided deeper insights into the correlation between stock price volatility and trading volume. The rolling sum (volumeSum) and nextVolume demonstrated clear predictive potential regarding future trading volume behavior.

Critique of AI

Prompt used “Expand stock analysis with volatility and volume correlation metrics."

The generated code included basic rolling averages but lacked financial analysis standards like logarithmic returns.
